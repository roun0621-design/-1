1. 분석 개요

항목내용
분석 목적대회 운영 시스템에 저장한 페이싱 설정을 WaveLight 컨트롤러에 자동으로 전송하고, 경기 진행 상태와 조명 상태를 함께 관리하기 위해 컨트롤러가 받는 통신 방식을 파악한다.
분석 대상WaveLight 컨트롤러의 운영 화면 "Wavelight event tool" (화면 코드 버전 5.0, 하드웨어 버전 5.00, 한 바퀴 조명 400개)
접속 방식컨트롤러와 같은 네트워크의 PC 에서 http://<컨트롤러 주소>:5001/wavelight
분석 방법① 컨트롤러가 브라우저에 내려 주는 화면 코드(HTML · JavaScript) 열람 ② 상태 조회 응답 관찰 ③ 화면 코드를 그대로 옮긴 모의 컨트롤러에서 동작 재현 ④ 실제 장비에 시험 송신(대기 · 취소 · 출발)
분석 일자2026년 11월 21일

2. 컨트롤러의 구성

  • 컨트롤러 안에 작은 웹 서버가 있고(포트 5001), 운영자는 브라우저로 운영 화면을 연다. 화면에서 누르는 버튼은 모두 이 웹 서버로 가는 HTTP 요청이다.
  • 로그인이나 키가 없다. 같은 네트워크에 있는 PC 는 누구나 같은 요청을 보낼 수 있다. 따라서 별도의 장비 개조 없이 소프트웨어만으로 연동할 수 있다.
  • 화면에는 조명 줄이 10개 있다. 줄마다 색, 출발선, 구간(거리 · 시간)을 정해 출발시킨다. 한 줄이 페이스 하나에 해당한다.
  • 웹 서버는 한 번에 요청 하나씩 처리한다. 화면은 5초마다 상태를 조회한다.

3. 통신 인터페이스

주소기능요청 본문 (JSON)
GET /command09상태 조회없음. 응답은 숫자 60개의 배열(5장)
POST /command06줄 시작(프로그램 전송)줄 번호 · 구간 목록 · 색 · 출발선 · 출발 방식(4장)
POST /command08줄 취소{ "runnerArrayNumber": 줄 번호 }
POST /command12출발(Fire)없음. 출발 신호를 기다리는 줄이 모두 출발
POST /command10조명 전원 · 밝기{ "lampsOnOff": 0|1, "lampPower": 0~100 }
POST /command14, /command17진행 중 숨김 · 파일럿{ "runnerArrayNumber", "isHideEnabled" | "isPilotEnabled" }
GET /loadSettingsFromAFile사용자 지정 출발선응답 예: {"customStartingLineLampNumbers": ["351"]}

요청 머리글은 Content-Type: application/json;charset=UTF-8. 연동에는 위 표의 앞 네 가지와 마지막 한 가지만 쓴다.

4. 프로그램 전송 메시지 (command06)

{
  "runnerArrayNumber": 1,                 // 줄 번호 1~10
  "Steps": [                              // 구간 목록 — 순서대로 진행
    { "NumberOfLamps": 400, "Duration": 60000 },
    { "NumberOfLamps": 400, "Duration": 61000 }
  ],
  "colourNumber": 0,                      // 색
  "startingDelay": 100,                   // 출발선의 조명 번호
  "startingDelayInSeconds": 255,          // 255 = 출발 신호 대기, 0 = 바로 출발
  "isHideEnabled": 0,
  "isPilotEnabled": 0
}
항목뜻과 규칙
Steps[].NumberOfLamps그 구간에 조명이 가는 거리. 조명 1개가 1m. 16비트(최대 약 65,000).
Steps[].Duration그 구간에 걸리는 시간(밀리초). 24비트(최대 약 16,777초).
colourNumber0 초록 · 1 파랑 · 2 흰색 · 3 빨강
startingDelay결승선을 0 으로 한 출발선 조명 번호. 결승선에서 끝나려면 (400 − 조명 거리 % 400) % 400. 화면의 보기: 400 → 0, 300 → 100, 200 → 200, 100 → 300, 1500 → 100, 1마일 → 391, 2마일 → 381.
startingDelayInSeconds255 로 보내면 줄이 출발 신호를 기다리는 상태가 되고, 이후 /command12(Fire) 또는 출발 신호 장치로 출발한다.

응답은 HTTP 200 과 본문 1바이트(ACK, 0x06)이다.

5. 상태 응답 (command09)

숫자 60개의 배열이다. 마지막 두 칸이 앞 58칸의 합(상위 · 하위 바이트)이므로, 합이 맞지 않는 응답은 버린다.

위치내용
0 ~ 9줄 1 ~ 10 의 상태 — 0 비어 있음 · 2 출발 신호 대기 · 1 진행 중
10조명 전원 (0 꺼짐)
11 ~ 14하드웨어 버전 글자 (예: 5.00)
15 ~ 16한 바퀴 조명 수 (예: 400)
25조명 밝기(%)
43, 44온도, 선 전력(×0.1)
58 ~ 59검사 합

6. 프로그램 파일(.pc2)

  • 화면의 Complex 창에서 Load file 로 읽는 파일이다. 조명 한 줄이 파일 하나이며 내용은 JSON 배열이다: [{"step-distance": "400", "step-pace": 60.0}, …] — 거리(m)와 그 구간의 시간(초).
  • 파일은 브라우저가 읽을 뿐 컨트롤러에 저장되지 않는다. 즉 파일을 넣어 두면 자동으로 읽히는 폴더는 없다. 자동 전송은 4장의 메시지로 해야 한다.
  • Complex 창을 닫을 때(Confirm) 다음 구간이 있으면 창이 닫히지 않는다: 한 구간이 19.2초 미만이거나, 초 × 거리 × 2.5 가 16,777,000 을 넘는 구간(예: 10,000m 를 한 구간으로). 구간 칸은 56개이다.

8. 연동할 때의 유의 사항

  • 인증이 없으므로 컨트롤러 네트워크에는 운영 PC 만 연결한다.
  • 운영 화면을 여는 것만으로 조명 전원이 꺼져 있으면 /command10(전원 끔)이 한 번 나간다. 연동 프로그램은 화면을 열지 않고 필요한 요청만 보낸다.
  • 시간 단위는 장비 설정에 따른다. 이 장비는 "구간 전체 초" 방식이다. 다른 장비에 연결할 때는 설정 파일(static/js/wavelight.js)을 먼저 확인한다.
  • 3000m 장애물은 물웅덩이 구간에서 선수가 달리는 거리(121.41m)와 조명이 가는 거리(100m)가 달라, 조명 기준 2,850m · 15구간으로 환산한다. 출발선은 계산값 350 이며 이 장비에는 사용자 지정 출발선 351 이 저장되어 있다.
  • 2000m 장애물의 환산 거리와 400개가 아닌 조명 구성은 확인하지 않았다.
