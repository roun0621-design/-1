1. 목적과 범위

구현 항목설계 내용
페이싱 시나리오 자동 생성 · 전송 모듈운영 시스템에 종목과 목표 기록(구간별 랩타임)을 입력하면 컨트롤러가 받는 페이싱 프로그램(구간 · 색 · 출발선)을 자동으로 만들고, 현장 PC 의 에이전트가 컨트롤러에 전송한다. 줄마다 파일을 불러오고 색과 출발선을 맞추던 수동 설정을 대체한다.
실시간 동기화 제어 · 통합 운영 콘솔운영 시스템의 경기 진행 상태와 컨트롤러의 조명 줄 상태를 한 화면에 보여 주고, 둘이 맞는지 판정한다. 경기가 진행 중이 되면 해당 종목을 자동으로 올릴 수 있고, 출발 · 취소를 같은 화면에서 한다.

컨트롤러의 통신 방식은 별도 문서 「WaveLight 컨트롤러 프로토콜 분석서」에 정리했다. 이 문서는 그 위에 얹은 구조를 설명한다.

3. 페이싱 프로그램 자동 생성

3.1 입력

관리 화면 › 페이싱 라이트에서 성별 · 부 · 종목을 고르고, 색(초록 · 빨강 · 흰색 · 파랑)마다 구간 거리와 랩타임을 입력한다. 구간이 하나면 목표 기록 하나만 넣으면 된다. 부(대학부 · 일반부 등)마다 따로 둘 수 있다.

3.2 변환 규칙

규칙내용
색 한 줄 = 프로그램 하나구간 거리 → 조명 수(1m = 1개), 랩타임 → 밀리초. 구간은 입력한 그대로.
3000m 장애물 환산물웅덩이 구간은 선수가 121.41m 를 달리는 동안 조명이 100m 를 간다. 250 → (100 + 300) × 6 → 100 → 100 의 15구간(조명 2,850m)으로 나누고 입력한 빠르기를 구간마다 나눠 담는다. 운영사 예시 파일 7개와 글자 단위로 일치한다.
출발선 계산결승선에서 끝나도록 (400 − 조명 거리 % 400) % 400. 800m → 0, 1500m → 100, 3000m · 5000m → 200, 3000m 장애물 → 350. 컨트롤러에 사용자 지정 출발선이 3m 안쪽에 저장되어 있으면 그 값을 쓴다(현장에서 맞춘 값 우선). 운영자가 콘솔에서 고칠 수 있다.
색 번호초록 0 · 파랑 1 · 흰색 2 · 빨강 3
파일(.pc2) 범위 맞추기손으로 불러올 때를 위한 파일은 프로그램 화면의 제한에 맞춘다: 19.2초 미만 구간은 빠르기가 비슷한 이웃 구간과 합치고, 너무 긴 구간은 같은 빠르기로 나눈다. 전체 거리 · 기록은 같다. 컨트롤러에 직접 보내는 값은 이 제한이 없어 원래 구간 그대로다.
파일 이름영문만: <종목>_<성별>[_<부>]_<기록>_<색>.pc2 (예: 3000mSC_Men_Senior_9-05_Green.pc2)

4. 전송 흐름

'자동 올리기'를 켜 두면 운영자의 '올리기' 대신, 서버에서 받은 경기 상태가 '진행 중'으로 바뀌는 순간 에이전트가 같은 전송을 한다. 출발은 어느 경우에도 운영자의 Fire 또는 출발 신호 장치로만 한다.

5. 경기 진행 상태와 조명의 동기화

5.1 두 상태의 출처

상태출처값

조명 줄 상태컨트롤러 상태 조회(1초마다)줄마다 비어 있음 · 출발 신호 대기 · 진행 중

5.2 판정

경기조명콘솔 표시

A 종목 진행 중올라간 줄 없음어긋남 — "조명이 올라가 있지 않습니다"
A 종목 진행 중B 종목이 올라가 있음어긋남 — "경기는 A 인데 조명은 B"

5.3 진행 표시와 종료

출발 시각(콘솔의 Fire, 또는 다른 곳에서 출발해 상태가 '진행 중'으로 바뀐 순간)부터의 경과 시간으로 줄마다 진행 막대와 현재 구간(예: 2 / 4)을 표시한다. 프로그램이 끝나 컨트롤러가 줄을 비우면 에이전트가 이를 알아채 목록에서 지우고 "끝남 — 출발 뒤 1:48.4 (목표 1:48)" 과 같이 기록한다.

7. 안전 설계

  • 올리는 것만으로는 출발하지 않는다. 전송은 항상 '출발 신호 대기'로 하고, 출발은 사람이 한다. 자동 올리기도 대기까지만 한다.
  • 조명 전원 · 밝기는 건드리지 않는다. 취소는 이 콘솔에서 올린 줄만 한다. WaveLight 화면에서 올린 줄은 표시만 한다.
  • 전송 전에 확인한다: 상태 응답의 검사 합, 한 바퀴 조명 400개, 빈 줄 수. 모자라면 아무것도 보내지 않는다.
  • 컨트롤러 조작(올리기 · Fire · 취소)은 한 번에 하나씩 순서대로 처리한다.
  • 전송 요청은 다시 보내지 않는다(중복 전송 방지). 상태 조회만 한 번 더 시도한다.
  • 콘솔은 그 PC 에서만 열리고, 다른 웹 페이지가 보낸 요청은 받지 않는다.
  • 인터넷이 끊기면 마지막으로 받은 내용으로 계속 운영할 수 있다.

9. 검증과 한계

  • 자동 시험: 변환 규칙, 프로그램 범위 맞추기, 전송 · 출발 · 취소, 경기 상태 판정, 자동 올리기를 모의 컨트롤러로 시험한다(tests/api/73_pacing_wavelight.test.js, 74_wavelight_agent.test.js).
  • 실제 장비: 1500m 3색 전송 · 취소, 800m 3색 자동 올리기 → Fire → 완주. 세 줄이 목표 기록(1:48 · 1:51 · 1:54)에 맞춰 끝났다.
  • 한계: 컨트롤러는 조명의 현재 위치를 알려 주지 않으므로 진행 막대는 출발 시각과 프로그램으로 계산한 값이다. 출발 시각을 콘솔 밖에서 알아챌 때는 상태 확인 주기(1초)만큼 오차가 있다. 출발선 위치는 400m 트랙 기준 계산값이며 경기장마다 현장 확인이 필요하다.
